## Fixed contract (both handoff packages)
Plan.schema.json now requires author and intent_guard. intent_guard: source_ref string, requirements array of {id (nonempty unique),quote (nonempty exact substring of source), outcome (min8chars)}; review_ref string pointing independent JSON review receipt; acceptance object {command,expect_exit_code[,expect_contains]} for original purpose end-to-end check. Task packet.schema.json adds requirement_ids string array; in-plan tasks must reference known requirement IDs and union must cover every requirement. Investigative tasks also mapped. Existing task/result fields preserve existing conventions/model inheritance/Claude model_hint.
Review receipt: reviewer string != plan.author; verdict aligned|blocked; source_sha256/spec_sha256 exact lowercase hex digests of referenced source and plan.spec_ref; requirements_covered exact unique set all requirement IDs; unapproved_changes empty array; evidence nonempty explanatory string. Presence/hashes/coverage checks are machine-verifiable; semantic correctness and actual independence are not cryptographically proved. Do not claim that hashing proves intent alignment or code tests prove user intent. Source/spec changes invalidate receipt and emit. No reviewer selfapproval allowed. A source quote matching only keywords is not semantic alignment; skill must require real independent source/spec review.
