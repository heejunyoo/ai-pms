# 핸드오프 — Phase 분해 · 서브에이전트 위임

**서브에이전트는 이 리포를 모른다.** 내가 조사해서 문서로 만들어 주지 않으면 그럴듯하게 지어낸다.
지어낸 것을 고치는 비용 > 조사 비용. 이 스킬의 전제는 그것 하나다.

핵심 산출물은 근거를 담은 `spec.md`와 실행 계획 `plan.json`이다. 내 컨텍스트가 아니라 디스크에 남긴다.

## 0. 이 절차를 쓸 작업인가

**쓴다** — 셋 다 참일 때:
1. 변경이 파일 2개 이상 또는 단계 2개 이상에 걸친다
2. 성공을 **실행해서** 판정할 수 있다(테스트·빌드·린트·스크립트 중 하나라도)
3. 중간 산출물(로그·검색결과·파일 덤프)이 내 컨텍스트에 남을 필요가 없다

**안 쓴다:** 한 파일 수정으로 끝남 · 판정 명령을 못 만들겠음 · 되돌리기 어려운 실행(배포·삭제·마이그레이션·외부 쓰기).
마지막 항목은 **계획만 하위에 맡기고 실행은 내가** 한다.

---

## 1. 근거 수집 — 기준선과 재현을 구분한다

초기 조사 결과를 경로와 심볼로 남긴다. 구현 중 소스·요구사항이 바뀌면 영향을 받는 근거만 다시 확인한다.

### 산출물 위치 (리포마다 다르므로 발견한다)

이미 있으면 그걸 쓴다: `.specify/` · `docs/specs/` · `specs/` · `.codex/specs/`
없으면 `.codex/specs/<기능-슬러그>/` 를 만든다. git 리포가 아니면 스크래치패드.
`spec.md`(사람이 읽는 근거) 와 `plan.json`(기계가 읽는 계획) 두 개를 여기 둔다.

### 반드시 확인할 6가지 — 스택 무관

| # | 확인할 것 | 실패하는 방식 |
|---|---|---|
| 1 | **검증 명령**. 기존 기준선과 버그 재현·새 기능의 합격 기준을 나누어 실제 결과를 확인한다 | 추측한 명령을 패킷에 박으면 하위 모델이 전부 실패로 판정한다 |
| 2 | **변경 지점**: 파일 경로 + 심볼 이름 | "auth 쪽 어딘가"로 넘기면 하위 모델이 파일을 새로 만든다 |
| 3 | **본보기 1개**: 이미 같은 패턴으로 구현된 곳 | 없으면 하위 모델이 자기 스타일로 쓴다 |
| 4 | **경계**: 건드리면 안 되는 파일·모듈 | 범위가 조용히 넓어진다 |
| 5 | **규약**: 이 리포의 명명·에러처리·주입 방식 (주변 코드에서 뽑는다) | 리뷰에서 전부 되돌아온다 |
| 6 | **미해결 설계 판단** | **여기서 내가 정한다.** 남겨서 넘기면 하위 모델이 지어낸다 |

기존 기준선의 실패는 기록한다. 버그 재현이나 새 기능 테스트는 구현 전 기대한 이유로 실패할 수 있다. `acceptance.command`는 구현 뒤 통과해야 할 검증이며, 실행하지 않은 명령을 실행했다고 쓰지 않는다.
6번이 남아 있으면 Phase 분해로 넘어가지 않는다.

## 2. Phase 로 쪼갠다

`plan.schema.json` 을 채운다. 채워진 예시는 `example.plan.json`(반환 예시는 `example.result.json`).
경계 규칙 셋:

- **Phase 끝 = 검증 명령이 통과하는 상태.** 통과하지 못하는 중간 상태로 Phase 를 끊지 않는다
- **같은 Phase 안의 태스크는 서로 다른 파일을 만진다.** 겹치면 병렬로 못 돌린다
- **순서 의존은 `depends_on` 으로만** 표현한다. 산문으로 "먼저 A 하고"라고 쓰지 않는다

---

## 3. 태스크를 서브에이전트 경계에 맞춘다

각 태스크는 목표 하나, 독립 검증 명령 하나, 명시된 파일 경계를 가져야 한다. 설계 판단이 남았거나
다른 태스크와 같은 파일을 동시에 만져야 하면 먼저 합치거나 `depends_on` 으로 직렬화한다.

### 모델과 추론 수준은 기본적으로 상속한다

모델과 추론 수준은 부모 설정을 상속한다. 패킷이 채워졌다는 이유만으로 추론을 낮추지 않는다.
사용자가 특정 모델·수준을 요청하면 그 요청을 따른다. 더 낮은 추론을 선택하려면 작업 난도와
검증의 충분성을 판단하고, 비용·속도만으로 검증 능력을 축소하지 않는다.

실패한 태스크는 증거를 읽고 설계·추론 문제와 환경·권한 문제를 구분한다. 원인에 맞게 접근을
바꾸며, 같은 접근의 재시도 상한을 진행 가능한 다른 작업까지 중단하는 근거로 쓰지 않는다.

## 4. 검증 → 디스패치

```
python3 ~/.agents/skills/handoff/validate.py plan <plan.json>
python3 ~/.agents/skills/handoff/validate.py emit <plan.json> <task_id>   # 프롬프트 생성
```

`ERROR` 가 있으면 디스패치하지 않는다. `WARN` 은 읽고 판단한다.
`emit` 이 뽑아 준 블록을 `spawn_agent.message` 에 싣는다. `tools_allowed` 와 `budget` 은 작업 패킷의
가이드일 뿐 API 수준의 권한·턴 제한이 아니다. 실제 권한은 부모와 제품 정책이 결정한다.

- 독립 작업이면 `fork_turns="none"` 과 자기완결 패킷을 사용한다. 최근 대화가 꼭 필요할 때만 최소 턴을 전달한다.
- 기본 디스패치에서는 모델·추론 override를 생략하고 부모 설정을 상속한다.
- `depends_on` 이 끝난 태스크만 디스패치한다.
- 현재 동시 실행 한도와 살아 있는 에이전트는 `list_agents` 로 확인한다. 한도를 숫자로 하드코딩하지 않는다.
- 전체 대화 히스토리나 파일 덤프를 넘기지 않는다. 필요한 경로·심볼·근거만 패킷에 둔다.

## 5. 돌아온 것을 처리한다

```
python3 ~/.agents/skills/handoff/validate.py result <result.json> --plan <plan.json>
```

| 반환 | 할 일 |
|---|---|
| `complete` + `unmet_constraints` 비었음 | `acceptance_run` 의 exit code 와 출력을 **내 눈으로 확인**하고 수용 |
| `unmet_constraints` 있음 | 계획을 고친다. 비었다고 가정하고 다음 Phase 로 가지 않는다 |
| `partial` | 남은 조각만 새 태스크로 쪼갠다. 통째로 재시도하지 않는다 |
| `failed` / 스키마 위반 | 패킷을 고쳐 **1회만** 재발행. 또 실패하면 내가 하거나 사용자에게 보고 |

Phase 를 닫기 전에 그 Phase 의 `exit_check` 를 **내가 직접 실행**한다. 하위 모델의 자기보고로 닫지 않는다.

## 자가감사 (디스패치 직전)

- [ ] `acceptance.command` 를 내가 실제로 돌려 봤는가 (추측 아닌가)
- [ ] `edit_points` 에 파일 경로와 심볼이 둘 다 있는가
- [ ] 설계 판단이 하나도 안 남았는가 (`open_decisions` 비었는가)
- [ ] `already_tried` 에 이번 세션에서 해본 것이 들어 있는가
- [ ] 실패하면 무엇을 잃는지 한 문장으로 말할 수 있는가
- [ ] 모델·추론 수준을 불필요하게 낮추지 않고 사용자 override를 보존했는가

## 안 하는 것

- **조사 없이 패킷 쓰기.** 이 스킬의 존재 이유가 §1 이다
- **전체 히스토리 전달** 또는 파일 내용 통째 삽입. 경로와 발췌를 준다
- **근거 없는 confidence 수용.** evidence 와 같이 올 때만 의미가 있다
- **한 파일 고치는 일에 이 절차 씌우기.** §0 을 다시 읽는다
- **Phase 를 검증 불가능한 지점에서 끊기**

## 규모가 커지면

태스크가 많아도 모든 노드를 한꺼번에 만들지 않는다. Phase별 준비 노드만 디스패치하고 결과를
검증한 뒤 다음 의존 노드를 연다. 별도 그래프 프레임워크나 상태 저장소는 반복 필요가 입증되기 전에는 만들지 않는다.
