# 공개 샘플과 실제 로컬 도입 화면의 정보 구성 일치

실제 Chrome 비교: 로컬 Paper는 4단계/7작업·문서·API 참고와 version3 management가 있다. 공개 sample-support/intake/report는 반복된 3단계/4작업과 빈 documents/connections/management로 축약되어 핵심 정보 경로를 보여주지 못했다. 레이아웃의 공통 UI는 현재 정본이지만 내용 parity가 없다. 이전 배포 승인에 따른 기존 Vercel/GitHub 수정 배포는 부모가 맡는다.

가상 프로젝트 세 개와 기존 IDs/라우트는 보존하되 실제 도입에 가까운 서로 다른 계획을 작성한다. support 4단계/최소7작업, intake 최소8단계/최소21작업, report 4단계/최소7작업. 프로젝트마다 구체적 범위·Phase 목표·담당·이유·다음 행동·완료 조건이 달라야 한다. 10단계 예시로 가로 스크롤/정렬을 검증한다. 기존 scope/implement/decision/verify IDs는 유지한다.

공개 catalog version3은 실제 로컬의 objectives/requirements/plans/artifact/work/updates를 같은 정확한 계약으로 사용한다. 가상 documents와 출처의 버전/날짜/발췌를 등록한다. annotations에는 단계에 귀속된 API/MCP 참고를 declared로 넣는다. observed 호출·runs·관측된 실행 sessions·실제검사·AI성공을 만들지 않는다. 기존 계약이 문서 등록 session_id를 event_count=0 legacy sessions로 집계하는 것은 문서 선언 식별자이며 실행 세션 관측이 아니다. model을 수동 변조하지 않고 문서 식별자와 연결된 zero-event 세션만 허용한다. documentary 완료는 현재 완료가 아니다. 날짜축을 만들지 않는다. declared/input/output은 각 근거대로 유지한다. 실제 비공개 데이터나 본문은 복사하지 않는다.

UI는 기존 shared human-view를 그대로 재사용한다. 긴 경고·다운로드 설명은 한 줄 가상 표시와 접힌 샘플 자료 안내로 줄인다. 원문 페이지도 실제 로컬과 같은 읽기 가능한 본문 폭/줄바꿈을 제공한다. 새 기능/계약/설치/Kit 변경은 없다. 기존 recorded-example 및 failed/stale/review_pending 반례를 보존한다.

검사 check_sample은 기존 안전/반례/불변식 검사를 유지하고 위 정보 구성과 실제 모델 문서·관리 구조·참고를 추가 검증한다. 부모는 실제 Chrome에서 public/local 전체계획/확인결과/실행/참고자료 경로를 비교하고 데스크톱 긴도표 정렬/스크롤과 원문/뒤로/리로드를 인수한다. 바이트일치만으로 parity완료를 판정하지 않는다.
