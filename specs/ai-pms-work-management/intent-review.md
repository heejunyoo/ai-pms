# 독립 목적·설계 검토

판정: **aligned** (목적 정합성 승인). 사용자 원문(source.md)과 PRODUCT-INTENT.md를 직접 대조하고, 지적한 두 완료 판정 문제의 수정본을 다시 읽었습니다. 로그 중심 화면을 사람 → 프로젝트 목표 → Phase → 원자 작업 → 검사/개입으로 바꾸는 명세는 요청 목적에 부합합니다.

## 목적별 확인

- **people:** 사람 한 명의 여러 프로젝트와 공동 프로젝트 한 건을 지원합니다. 담당 작업과 참여 이력을 구별하고, 선택 사람의 작업 집계와 프로젝트 전체 문맥을 구별합니다. 담당자 없는 문제를 임의의 사람에게 귀속하지 않습니다.
- **work:** 목표·Phase·원자 작업·의존성·인수기준·문서·runner 근거·승인을 연결합니다. 현재 근거와 담당자·인수기준·의존성·필수 검토가 충족되어야 완료로 판단합니다. 세션/도구/MCP 횟수와 선언된 결과를 완료로 승격하지 않습니다.
- **interventions:** 누락된 담당자/인수기준, 막힘, 실패, 검토 대기, 재검증을 구체적인 다음 행동으로 제시하고 해당 작업으로 연결합니다. 프로젝트 수준 문제는 별도 범위로 보존합니다.

## 재검토로 닫은 문제

1. **빈 Phase의 완료 우회:** 프로젝트 완료 조건을 모든 선언 Phase의 완료로 수정했습니다. 작업이 없는 Phase와 선택 작업만 있는 Phase는 미관측으로 남아 프로젝트 완료를 막습니다. 해당 반례를 검증 요구에 추가했습니다.
2. **변경된 기준에 과거 승인 재사용:** task_sha256에 plan id/version/at, task, 현재 기준 전체 정의와 최신 테스트 계획 전체 레코드를 포함합니다. review 시각도 work.at와 적용되는 최신 testplan.at 이후여야 합니다. 같은 산출물·같은 기준 ID에서 정의를 바꾸고 재검사한 경우 과거 승인을 재사용하지 못하도록 반례를 추가했습니다.

## 인수 경계

Python/JS 재계산, 위조 완료 거부, snapshot 보존과 실제 브라우저의 사람 필터 → 목표 → Phase/작업 → 개입 경로, 키보드·390px 검증을 요구합니다. 실제 로컬 subprocess의 실패 → 통과 → 변경 후 재검증도 별도 근거로 남기도록 했습니다.

이 승인은 설계의 목적 정합성에 한정합니다. 구현 정확성이나 공개 배포 성공, 실제 여러 사람의 운영 완료를 증명하지 않습니다. 공개 합성 샘플, 선언된 runner/검토 귀속, 실제 로컬 검증 및 아직 유예된 자동 다중 PC 수집의 경계는 계속 유지해야 합니다. 현재 원문·명세의 정확한 SHA-256은 intent-review.json에 기록했습니다.
