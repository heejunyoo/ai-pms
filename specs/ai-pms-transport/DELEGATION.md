# 승인 A 작업 단위와 하위 모델 이관

이번 원자화 기준은 **한 작업의 실패·재시도·검증을 독립적으로 판단할 수 있는가**입니다. 함수 수나 파일 수만으로 나누지 않습니다. 공유 계약을 먼저 부모가 정하고, 수신함의 영속 기록과 ACK처럼 함께 지켜야 하는 조건은 한 작업에 둡니다.

| 단위 | 하위 모델의 편집 범위 | 선행 조건 | 끝났다고 판단할 검사 | 부모 책임 |
|---|---|---|---|---|
| T1 인증 수신·집계 | common.py, receiver.py, test_receiver.py | 원문·명세 독립 검토, plan/emit 통과 | 실제 HTTP 인증·멱등 ACK·저장 실패·집계 충돌 | 공통 계약 확정, 코드 검토, Phase 종료 검사 |
| T2 송신·재시도 | sender.py, test_sender.py | T1 계약과 검사 통과 | outbox 영속성·재시작·ACK 분실·오프라인 복구 | T1과의 통합, 원본 보존 확인 |
| T3 중앙 전달 화면 | 기존 central.py, test_delivery_view.py | T1 상태 계약과 검사 통과 | 등록만 된 환경·heartbeat·대기/실패/충돌·잘못된 metadata | 실제 목록→상세→원본, 390px 화면 인수 |

T2와 T3는 수정 파일이 겹치지 않아 병렬로 진행합니다. T1은 공유 계약과 수신 후 집계 책임이 연결되어 있으므로 한 모델이 소유합니다. 작은 유틸리티별로 다시 위임하지 않습니다.

하위 모델에 넘기는 조건은 입력·출력, 수정 파일·심볼, 완료 검사, 제외 범위가 모두 확정된 경우입니다. 제품 목적·인증 귀속·ACK 의미·승인 범위·공유 계약 변경, 다른 작업 파일 수정이 필요한 경우는 부모에게 반환합니다. 같은 실패가 재발행 뒤에도 반복되면 원인을 부모가 판단하며, 실패 검사를 삭제하거나 합격 기준을 낮추지 않습니다.

최종 통합은 부모가 두 합성 사용자 context의 실제 loopback 전송→수신→집계→관리 화면을 확인합니다. 이 결과는 실제 두 사용자의 앱 훅 전달이나 제품 운영 완료를 뜻하지 않습니다. 외부 운영은 별도 승인 B입니다.
