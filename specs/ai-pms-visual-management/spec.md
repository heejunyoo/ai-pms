# 사람 중심 프로젝트 계획판과 직관적인 시각화

## 목적과 근거
source.md의 요구를 다수 사용자의 공동 프로젝트 계획·진척·판단에 적용한다. PRODUCT-INTENT.md를 축소하지 않는다. 전문가 미팅은 reports/visual-redesign/의 Astra/UX 검토와 부모의 교차검토이며 실제 고객 인터뷰가 아니다.

확인한 결함: human-view.js renderPhaseFlow는 WBS를 화살표 카드로 대체하고 renderDetail의 Phase 분기는 작업 통로를 삭제한다. renderTab은 세션 raw 목록 뒤에 목표 목록을 append한다. 상세 근거 markup은 9개 분류 탭이다. 기본 검사 check_experience.py는 통과했지만 위 사용성 실패를 검사하지 않는다. 실제 브라우저 연결은 현재 사용할 수 없다.

## 결정한 화면과 시각화
1. 사람별 프로젝트 목록: 목표·참여자·단계 완료/진행/판단 필요·수집된 세션 요약만 읽는다. 참여자는 같은 공동 프로젝트 안에서 책임을 구분한다. 이름 없는 작은 색 막대 대신 상태와 단계 이름을 함께 읽을 수 있는 요약을 제공한다.
2. 프로젝트 기본 화면: 전체 계층형 WBS를 주 시각화로 표시한다. Phase 목표·원자 작업·담당·상태·단계 종료 검사·최종 인수의 관계를 읽을 수 있어야 한다. Phase마다 접힌 원자 작업을 펼칠 수 있고 작업의 별도 주소로 이동한다. 선택한 사람의 담당 작업을 강조하되 공동 전체 계획과 다른 담당자 작업은 보존한다. 프로젝트 이름/목표와 간결한 참여자 요약은 위에 둔다.
3. 날짜가 없는 계획은 Phase 순서 축, 검토된 명시 일정이 유효하게 바인딩된 경우만 기존 날짜축을 사용한다. 전후 순서는 실제 의존성을 뜻하지 않는다. 임의 기간/ETA/납기/AI 점수/업무 성과 비율 금지. 작업 완료 수는 계획 작업 수일 뿐 소요 노력 비율이 아니다.
4. 상태는 텍스트·형태와 색을 함께 사용한다. 검증 완료/진행/막힘·검토 필요/기록 없음과 미래 계획을 구별한다. 문서상 완료는 현재 runner 검사 통과와 별도 표기하며 현재 최종 인수는 보수적 모델 그대로 유지한다.
5. Phase 상세는 목표·진척·API/MCP와 해당 Phase의 작업 통로를 제공한다. 작업 상세는 기존 담당·사유·다음 행동·완료 조건을 유지한다. 문서와 검사 원문은 해당 작업/단계에서 접어서 연다.
6. 일반 근거 진입은 '작업 결과/실행 이력/참고 자료' 등 실제 질문으로 구성하고 9개 원시 분류 탭을 첫 경험으로 노출하지 않는다. 기존 검사·문서·판단·인계·원본 기능과 기존 주소는 기술 근거 경로로 보존한다. 실제 사용자가 질문 없이 9개 탭을 탐색하게 하지 않는다. 조직 목표의 기존 관리 기능과 명시 기여를 삭제하거나 개인 목표에 강제하지 않는다.
7. 프로젝트 세션은 한 목록으로 제공한다. 운영 세션의 목표·실행 상태·목표 완료·시간·담당 작업을 먼저 표시하고 내부 ID는 접는다. 중복 raw + goal 목록은 금지한다. 사용자·환경·출처·원본 프로젝트를 포함해 식별을 보존하고 단순 session_id나 세션 수로 생산성/완료를 판단하지 않는다. legacy 기록은 목표 근거 부족으로 구분, 실제 문서 미리보기처럼 수집이 없으면 0회 성공 대신 기록 없음. 한 세션이 여러 작업에 연결된 경우를 보존한다.
8. 읽기 전용 처리함은 실제 막힘/검토 항목만 표시한다. 정상 ready/in_progress를 긴급 처리하지 않는다. 명시 다른 담당자 요청 제외, 프로젝트 공통 요청 구분, 문서 날짜/출처, 선언된 다음 행동 없음 유지.

## 구현 경계와 정본
UI 패킷만 specs/ai-pms-dashboard/human-view.js/css 및 dashboard.html HUMAN VIEW 블록을 수정한다. 기존 backend/계약/완료 계산/수신/전역 hooks/trust/자격은 변경하지 않는다. native DOM/link/details와 CSS로 구현하고 외부 디자인 패키지/API 의존성을 추가하지 않는다. canonical과 embedded는 byte 동일해야 한다. route/person/focus/delta/reset/정확한 text 안전성을 보존한다.

QA 패킷은 새 check_visual.py, QA 결과와 기존 human projection/experience 검사에서 바뀐 시각화 계약만 조정한다. 기존 의미/안전 검사 삭제·skip·약화 금지; 기존 WBS/행동 기술 근거 검사를 계속 유지한다. UI/QA는 파일 소유권을 나눠 병렬 실행한다.

문서 패킷은 docs/visual-management.md, Kit current_content.py의 마지막 한영 AI PMS 항목, docs-result.json만 수정한다. 부모가 앱/비공개 네 프로젝트/Kit runtime·ZIP/공개 checkout을 갱신하고 source.md에 보존한 기존 공개 승인 범위에서 기존 AI PMS·Kit·GitHub를 배포·게시한다. private 문서·로그·그래프는 공개하지 않는다.

## 인수 연결
시각화 요구 → 전체 계획/현재/남은/담당 질문 → p.work와 명시 문서·schedule → 기본 WBS/동일 프로젝트 책임 강조 → DOM에서 전체 Phase/작업/상태/바인딩/잘못된 인수 반례. 세션 요구 → 누가 무엇을 위한 몇 실행인가 → operations/legacy 식별 → 중복 없는 이력/목표 판정 → 서로 다른 사용자 같은 ID/다중 작업/기록 없음 반례.

명령 인수: python3 specs/ai-pms-visual-management/check_visual.py. 부모의 별도 실제 데스크톱 인수: 공동 프로젝트 전체 WBS/사람 선택/Phase 펼침/작업·막힘 상세/실행 이력/근거 진입/뒤로·reload를 실제 화면에서 확인하고 캡처한다. 실제 자료 문서 상태와 현재 검사를 혼동하지 않는지도 본다. 모바일은 제외한다. 브라우저 연결 불가면 소스 통합만 완료로 기록하고 UX·시각적 인수는 미완료로 남긴다. 스크린샷을 상상하거나 이전 캡처를 재사용하지 않는다.
