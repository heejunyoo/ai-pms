# 사람이 읽고 판단할 수 있는 프로젝트 전체 화면

## 실패와 근거
실제 Chrome에서 공개 프로젝트→분석 근거로 들어갔을 때 세 질문 버튼은 모두 선택되지 않고, 합성 기술 검사/phase-exit/runner/기준 서명 등의 원시 검사 목록이 바로 표시됐다. 실행 이력과 참고 자료를 선택해도 사용자의 질문에 답하는 요약 없이 기록 카드가 이어진다. 계획 화면은 담당 요약/API 영역/WBS를 수직으로 쌓는다. 버튼 세 개 추가는 전체 화면 리팩터링이 아니다.

정본 코드 specs/ai-pms-dashboard/human-view.js의 renderCards/renderShared/renderDetail/renderTab/humanSetupEvidence/humanRenderSessions와 human-view.css. 기본 렌더러 dashboard.html의 renderWork/renderTab/renderAction/renderFlowChecks는 기술 기록 보존용으로 재사용한다. 변경은 HUMAN VIEW 블록과 canonical JS/CSS에 한정하고 완료 계산/데이터 계약은 바꾸지 않는다.

## 구현 결정
1. 사람별 프로젝트 목록부터 프로젝트 요약/전체 계획/Phase/작업/결과 확인까지 일관된 정보 계층·간결한 타이포/레이아웃을 적용한다. 공동 WBS와 모든 담당자·원자 작업·명시 일정/단계축을 유지한다. 계획 상단에 목적, 현재 상태와 그 이유, 남은 조건/판단 및 직접 행동 경로를 우선 배치한다. 담당 요약과 API/MCP는 압축된 보조 영역으로 정리한다.
2. 프로젝트에 일관된 탐색을 둔다. 계획, 확인 결과, 실행 이력, 참고 자료가 사용자가 이해하는 역할이다. 기존 hash 주소와 사람 scope/history/reload를 유지하고 근거 진입의 기본 선택은 반드시 의미 있는 선택 상태와 설명을 가진다. 기술 분류가 선택된 옛 주소/명시 링크는 보존하되 일반 진입이 raw 목록으로 떨어지면 안 된다.
3. 확인 결과는 먼저 '무엇을 확인했나 → 결과 → 그래서 무엇을 해야 하나'를 사람이 읽는 카드/표로 설명한다. 단계의 검사 통과와 작업 미완료/사람 승인 대기/현재 버전 재검증은 함께 보여 모순처럼 보이지 않게 한다. phase-exit 같은 내부 ID를 제목으로 쓰지 않고 연결된 Phase/작업 제목·검사 범위로 대체한다. 확인 내용이 제목/완료 조건에도 없으면 '확인 내용 미기록'이라 표시한다. 기술 필드를 번역해 사업 결과나 새 의미를 발명하지 않는다.
4. 실행 이력은 왜 시작했나/누가 언제 실행했나/실행이 끝났나/목표를 확인했나/이어볼 작업을 앞세운다. 누락된 목표·종료·검증에 사람이 보완할 다음 항목을 설명하되 새로운 실제 작업 선언으로 저장하지 않는다. 내부 compound ID/runner/receipt/hash는 접힌 '원본 기록'에만 둔다. 기존 서로 다른 신원/다중작업/legacy 구분을 유지한다.
5. 참고 자료는 어떤 단계/목표를 위한 자료인가, 문서 종류와 날짜·버전, 자료로 알 수 있는 것과 현재 실행 검증의 차이를 설명하고 선택 원문을 접어 제공한다. API/MCP는 설정 기록과 실제 호출을 구별한다. 제공 데이터에 목적/내용이 없으면 누락을 명시한다. 실제 비공개 문서 발췌·링크를 삭제하거나 공개 샘플에 복사하지 않는다.
6. Phase/작업 상세에도 목적→결과/막힘→다음 행동→완료 조건→접힌 원본의 같은 구성과 탐색을 적용한다. 기술 원문은 필요할 때 선택해서 접근한다. HTML 문자열로 비신뢰 데이터를 삽입하지 않으며 textContent/el/native link/details를 쓴다. 기존 keyboard/focus/delta/reset 회귀를 보존한다.
7. 모바일은 기존 사용자 지시대로 제외한다. 실제 desktop Chrome에서 첫 진입→사람 선택→공동 계획→막힘 상세→확인 결과/실행/참고→Back/reload를 부모가 관측한다. 공개 배포는 이번 요청에 포함하지 않는다. 공개 샘플과 로컬 비공개 미리보기를 갱신하여 검토 가능하게 한다.

## 사용자 질문과 인수
전체 리팩터링 → '목표/현재/남은 조건/다음 행동을 어디서 읽나' → 기존 work/operations/documentary → 하나의 프로젝트 탐색과 요약/WBS/문맥 상세 → 실제 Chrome 시각 인수.
분석 근거 → '무엇을 확인했고 무엇이 남았나' → 현재 scope/revision 검사·필수 작업/승인·문서 → 결과 설명과 후속 경로/접힌 원문 → raw hash/runner/내부 ID가 기본 패널에 노출되지 않으며 unknown/failed/stale/documentary 반례를 명령 검사하고 Chrome에서 확인.

명령 인수: python3 specs/ai-pms-readable-project/check_readable.py. 기존 check_visual.py/check_experience.py/check_human_view.py 및 공개 전체 검사에서 의미·보안 검사는 삭제/skip/약화하지 않는다. 구조와 문구가 변경된 기대만 새 UX에 맞게 갱신한다. provider 훅/원격 실제 전달/모델 분석/사업 성과 검증을 새 UI 완료로 승격하지 않는다.
