# PMS 정보 구조 개선

토스 공식 Product Principles의 Value First, Clear Action, One Thing, Casual Concept을 PMS에 적용하는 설계 해석이다. 공식 TDS 설치나 토스 제품의 복제를 주장하지 않는다.
출처: https://toss.im/tossfeed/article/tossproductprinciples 및 https://toss.im/tossfeed/article/uxwriter-interview

## 확정된 구조
- 밝은 바탕, 파란 주요 행동, 충분한 여백, 사람에게 필요한 짧은 제목과 상태 중심의 일관된 시각 계층.
- 첫 화면: 사람 범위 선택 → 판단이 필요한 작업 → 프로젝트 목록. 통계는 보조 정보. 검색과 사람 선택은 상시, 상태/단계/목표와 MCP 필터는 펼침.
- JSON 파일/붙여넣기/내보내기는 헤더의 데이터 관리 펼침 아래. 합성 데이터 표시는 남긴다.
- 개입 항목은 프로젝트명·작업명·책임자·필요 행동을 각각 구분. 작업 확인 클릭은 해당 작업으로 스크롤/초점 이동. 처음 3개 이후 native details로 모두 확인 가능. 정상 의존 대기는 관리 판단과 구분.
- 프로젝트 카드: 누가 무엇을 만드는지 → 책임 작업 완료 n/N와 프로젝트 전체 구분 → 현재 단계 → 다음 판단. 최근 문서/변경/계획 ID 등은 펼침.
- 상세 주요 탐색은 작업 현황·목표/판단·문서. 나머지 검사·세션·이력·MCP 기록은 더보기로 모두 보존하며 키보드 탐색 가능.
- 첫 작업 화면은 완료 조건·상태·담당자 중심. ID/계획 해시/runner/선행 작업 상세는 근거 펼침에 유지. 실패/승인/막힘/기준 누락/재검증을 완료와 혼동하지 않는다.

## 경계와 검증
기존 Python/JS exact contract와 사람 귀속 및 전체 완료 판정 변경 금지. 데이터/API/DB/인증/전역 hooks/새 의존성 변경 없음. 기존 테스트 유지. 원본 정본 dashboard.html만 편집, 생성 HTML은 기존 build_dashboard_app.py로 재생성. 부모가 공개 반영/배포 담당.
검증: 기존 check_ui_work.py, IA 구조 및 DOM 행동 검사, 빌드; 가능하면 실제 데스크톱/390px 브라우저에서 사람 선택→개입→작업→근거/키보드/JSON 오류 경로. 브라우저 불가 시 미검증을 기록하며 완료를 과장하지 않는다.
