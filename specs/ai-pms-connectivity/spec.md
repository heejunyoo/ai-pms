# AI PMS connectivity release

Purpose: multi-user, multi-session projects remain the management unit. Add MCP/data-source evidence to understand which dependency a project uses, where calls fail, what data references are exposed, and which artifacts have explicit references. Tests for current project revision still govern completion; connectivity never promotes completion.

Baseline: python3 specs/ai-pms-dashboard/verify_dashboard.py passed before modification (5 projects). Existing stdlib central.valid_event validates exact v1 event; transport calls this validator. logger.hook_event currently reduces raw MCP name to MCP and drops input/output. portfolio.build_model uses explicit actor/environment/project source keys. ## Fixed contract
Keep event v1 valid unchanged. v2 keeps the same top-level keys, schema_version=2, adapter_version='2'; observed tool event data optionally has exactly {connection: C}. C has exact fields server,tool,status,duration_ms,operation,resources,artifact_refs.
server and tool are identifier or null. status=requested|completed|failed|unknown. duration_ms=null or integer 0..86400000 (provided by adapter only; never guessed). operation=read|write|delete|unknown (unknown unless explicitly declared in reviewed metadata/map; tool success is not database audit). resources max32: exact {id,kind,label,evidence}, id identifier, kind=database|document|repository|api|file|unknown, safe label max160, evidence=declared|input|output. artifact_refs max32 exact {id,version}, safe identifiers; explicit refs only, no temporal inference. No URLs, paths, queries, tokens, raw tool inputs or outputs are stored. resource identity is scoped to actor/environment; labels do not merge different users' resources.

Logger normalizes supported native hook events for Codex/Claude and safe documented Cursor/Gemini metadata where practical. MCP names can establish server/tool; native tool events establish call status. Safe metadata block pms_metadata may provide operation/resources/artifact_refs; native exposed metadata is evidence of a reference, not proof the downstream database was actually accessed. Add optional --resource-map JSON mapping raw tool name -> {operation,resources,artifact_refs}, reviewed locally, with all mapped resources forced to evidence=declared. No external network. Invalid optional metadata is dropped with missing_fields marker; strict imported v2 validation rejects malformed/secret-like values. Tests prove actual hook stdin -> event -> central valid_event -> transport compatibility, v1 preserved, privacy filtering, unsupported data not guessed.

Dashboard model schema_version=2 when connectivity fields exist, accept/render/import/export v1 unchanged. Each v2 project's connections array has exact fields id,server,tool,status,duration_ms,operation,resources,artifact_refs,actor_id,environment_id,session_id,agent_id,tool_call_id,at,authority,source_ref. actor/environment match a project's sources; session_id and other IDs nullable; at UTC timestamp or null for configured catalog rows; authority=observed|declared. status additionally allows configured only for declared catalog row. Catalog v2 projects add connections with same exact fields except authority/source_ref (added by builder); status configured|unknown only; always declared. Catalog v1 stays unchanged. Model v2 includes connections:[] for projects with no evidence. Preserve old completion/catalog tests and source collision behavior. Calls are event observations, not necessarily unique executions; never count Pre/Post as two completed calls or associate by ambiguous call ID. Existing v1 MCP observations show identity unavailable rather than fabricate names. Resource/artifact references must remain provenance labelled; unknown artifact refs displayed as explicit reference, not verified artifact use.

UI: project cards indicate MCP/tool observations, portfolio connectivity overview lets administrator find affected projects by server or logical data source with scoped actor/environment identities. Add fifth detail tab 'MCP · 데이터' showing configured vs requested/completed/failed/unknown, server/tool, session/agent/call ID, duration/operation, data references/evidence, explicit artifact links and original provenance. Accessible text-based relationship path project -> actor/environment/session -> server/tool -> scoped resource -> explicit artifact; do not require graph library. Filtering/empty/error, safe rendering, keyboard tab navigation, import/export and 390px must keep working. Synthetic sample has configured-only, successful/failed calls, missing identity, shared server aliases on separate user environments, declared/input/output references and explicit artifact references. All data conspicuously synthetic.

Kit: bilingual AI PMS page, navigation, ELI20 responsibility/flow/limits, local logging examples and safe metadata contract, offline sample dashboard and public repo links. Canonical generator/checker/ZIP export updated, not handwritten generated pages. New app origin fixed https://ai-pms-dashboard.vercel.app (parent confirms availability before publication); repo https://github.com/heejunyoo/ai-pms. If unavailable parent supplies corrected URLs before final publish. Include v2 logger/new support module in ZIP and safe documentation. Do not install remote sender or change real-user hook trust.
