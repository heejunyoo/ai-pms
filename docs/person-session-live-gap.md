# 사람·세션·실시간 중앙 관리 — 현재 간극과 인수 기준

2026-10-02 최신 사용자 정정 및 Astra 독립 검토에 근거합니다. 조사 결과이며 구현 완료 보고가 아닙니다.

## 현재 판정

현재 공개 앱은 합성 데이터를 사용하는 오프라인 프로젝트/작업 검증 대시보드입니다. 토스 IA는 정보 배치를 바꿨지만 사람별 세션 관리와 실제 중앙 전달을 만들지 않았습니다. 외부에 동작하는 실시간 PMS로 소개할 근거는 아직 없습니다.

| 질문 | 실제 구현 | 간극 |
|---|---|---|
| 이 사람은 어떤 세션을 관리하는가? | portfolio.py 세션: id/actor_id/environment_id/event_count | 사람별 세션 탐색, 세션 목표/버전/연결 작업 없음 |
| 세션이 정상 완료됐는가? | logger의 session.start/turn.stopped/session.end | 종료 관측과 목표 인수의 별도 상태·근거 없음 |
| 어느 회사·팀 목표에 기여하는가? | management.py의 회사/개인 목표, 산문 성공 조건 | 팀 범위와 지표 관측, 세션 기여 제안/확인 없음 |
| 내 PC에서 로그가 잘 쌓이는가? | logger는 JSONL fsync, viewer는 파일 가져오기 | 실제 앱 호출 증거, 실시간 파일 추적, 실패/마지막 기록 표시 없음 |
| 중앙으로 계속 전달되는가? | sender는 날짜별 v1/v2 이벤트와 재전송 지원 | loopback 제한, v3 목표/작업/검사/승인 변경은 별도 JSON |
| 중앙 화면이 즉시 바뀌는가? | receiver의 영속 inbox ACK, 별도 aggregate CLI | 지속 집계/조회 cursor/화면 polling 없음; 배포 CSP connect-src none |

훅을 에이전트 작업과 분리하기 위해 logger는 기록 실패에도 exit 0을 반환합니다. 명령 성공은 기록 성공의 증거가 아닙니다. 직접 입력한 goal은 보존되지 않으며 task_id도 자동 연결되지 않습니다. 이 반례는 Astra의 합성 stdin 실행으로 확인했고 실제 앱 실행 증거는 아닙니다.

## 관리 화면의 기본 흐름

1. 사람 목록: 담당 목표, 관측된 세션, 목표 인수 대기/실패, 수집 지연 및 담당자가 판단할 항목.
2. 사람 상세: 프로젝트/환경을 가로지르는 세션 목록. 세션마다 시작 목표, 최근 활동, 종료 관측, 목표 인수 상태와 다음 행동.
3. 세션 상세: 목표 버전 → Phase/원자 작업 → 산출물 → 테스트 플랜 선정 근거 → 실패/수정/통과 → 필요한 사람 판단. 원본 event ID로 대조 가능해야 함.
4. 회사·팀 목표: 북극성 지표 정의/단위/기간/기준/목표/실측 근거와 연결된 개인 목표. 미연결·AI 제안·담당자 확인을 구별함.

세션 생명주기와 목표 인수 상태는 별도로 계산합니다. 종료됐지만 검사 실패인 세션, 열려 있지만 특정 목표를 달성한 세션, 종료 기록을 관측하지 못한 세션을 구별합니다. 여러 세션이 같은 작업에 기여해도 작업 완료를 중복 합산하지 않습니다. 담당자가 기여 연결을 확인한 사실은 인과 효과나 사업 성과 기여율을 증명하지 않습니다.

## 연결해야 하는 실행 경로

실제 앱 훅 → 로컬 영속 기록/수집 상태 → 지속 송신 → 인증된 중앙 inbox → 지속 집계 → 사람/세션/목표/검증 투영 → cursor 조회 → 열린 화면 갱신.

목표/계획 개정·검사 결과·승인·산출물 변경도 전달되어야 합니다. 기존 hook event만 보내면 검증 상태는 동기화되지 않습니다. 구체적인 버전/충돌/귀속 계약은 다음 명세에서 독립 검토하며 여기서 새 API 계약을 확정하지 않습니다.

기존 event ID, 재시도·중복 방지·충돌 보존·fsync ACK와 작업 완료 검증 계산기를 재사용합니다. 처음에는 cursor 기반 짧은 polling으로 충분합니다. 이벤트를 묶어 송신해도 각 이벤트의 개별 ID/저장/수신/적용 상태가 추적되면 됩니다. JSON 사용 자체가 문제가 아니라 전체 스냅샷 수동 가져오기에 갱신이 의존하는 것이 문제입니다.

PC의 위치를 알아야 할 필요는 없습니다. 참여 환경이 등록된 목적지로 outbound 연결합니다. 실제 중앙 목적지·사용자 귀속·관리자 조회 권한·TLS/자격 관리와 보존 범위는 원격 인수 전에 정합니다. 실제 비공개 로그를 공개 합성 샘플에 보내지 않습니다.

## 외부 공유 전 인수 조건

1. 실제 앱 두 참여 환경에서 같은 event/session ID가 로컬 파일 → 중앙 inbox → 집계 → 화면까지 이어짐을 확인합니다. 합성 stdin/loopback 증거를 별도로 표시합니다.
2. 종료와 목표 달성을 구별하고, 목표 개정·산출물 변경 시 이전 통과 근거를 재검증으로 전환합니다.
3. 로컬 쓰기 실패·단절·ACK 유실·집계 중단을 화면에서 구별하고, 복구 후 중복 없이 반영합니다. 로컬 저장/중앙 수신/화면 적용 시각과 지연을 구별합니다.
4. 목표/작업/테스트 플랜 변경·검사 실패→통과·사람 판단이 JSON 재가져오기 없이 열린 화면에 반영됩니다. 초기 종단 지연 목표 5초는 제안이며 실제 관측치로 검증합니다.
5. 실제 북극성 관측과 기여 제안을 구별하고 동일 산출물의 성과를 중복 계산하지 않습니다. 실제 브라우저에서 사람 → 세션 → 근거 경로와 390px 사용성을 확인합니다.

## 이번 검토의 증거와 경계

Astra /root/astra_work_intent는 logger·portfolio·management·sender·receiver·빌드 경로를 독립 열람하고 합성 logger 반례를 실행했습니다. 부모는 test_sender.py 및 test_receiver.py를 재실행해 통과했습니다. 이는 재사용 가능한 로컬 전송 기반의 확인이며 실제 앱 훅·원격 두 사용자·실시간 UI 검증이 아닙니다. 이번 변경은 문서에 한정하고 새로운 계약·제품 코드·전역 훅·배포는 변경하지 않았습니다.
