## 최신 증거의 유효 범위와 재확인

- 이 검토에서 `python3 ~/.agents/skills/handoff/validate.py selftest`를 실행해 ALL PASS를 확인했습니다. 기존 guard를 폐기할 근거는 없습니다. 의미상 잘못된 명세를 찾아낸다는 증거는 아닙니다.
- `python3 specs/ai-pms-action-detail/check_action_detail.py`를 실행해 PASS를 확인했습니다. 출력도 browser reload/history/layout은 부모 QA라고 명시합니다. 새 검사를 더 늘리기보다 이 구분을 보존해야 합니다.
- action-detail 독립 리뷰는 source/mock-DOM/parity이고 실제 브라우저 확인은 false입니다(`code-review.json:31-40`). 부모의 브라우저 관찰은 별도 근거입니다(`browser-observation.json:17-25`). 따라서 리뷰 PASS가 무의미했던 것도, 제품 수락을 증명했던 것도 아닙니다. scroll/focus/nested disclosure 등 구체 결함을 잡은 유효한 검토입니다.
- 최신 `browser-observation.json:24`는 모바일 offscreen pointer 자동화가 불안정하여 keyboard로 Bob 필터를 확인했다고 기록합니다. 원래 pointer/touch 경로는 남은 미검증입니다. 자동화 실패만으로 사용자 pointer 버그를 확정할 수도 없습니다. 실제 scroll-into-view 후 pointer/touch 재현으로 어느 쪽인지 판정해야 합니다.
- 공개 3페이지 릴리스 기록은 있으나 실제 provider hook/원격 두 사용자 전달과 전체 제품 완료는 false입니다(`release-proof.json:28-33`, `NEXT_SESSION.md:5-7,35`). 합성 일정, direct applyChanges, 파일 byte 일치는 각각 자기 범위에서 유효하며 실운영 증거가 아닙니다. 이번 검토는 이 기록을 읽었고 배포를 재검증하지 않았습니다.

## 제안의 반증 조건

- 과거 원문과 명세에 같은 관리 질문·화면 행동 인수가 이미 정확히 있었고 당시 실제 경로로도 통과했음을 확인하면, '인수 번역 누락' 대신 새 요구/선호 변화나 이후 회귀로 원인을 수정해야 합니다.
- 다음 UI 변경에서 표를 채웠는데도 관리자가 담당·막힘·다음 행동을 못 찾으면 문서 추가는 효과가 없었던 것입니다. 항목 수를 늘리지 말고 실패 화면·데이터 결핍을 고칩니다.
- 두 번 실패 후 접근 전환이 너무 이른 포기를 유발하면, 중단 대상은 같은 원인가설의 반복이며 다른 진행 가능한 작업은 계속한다는 경계를 적용합니다(`handoff/SKILL.md:83-84`).
- pointer 재검증이 정상 통과하면 그 경로의 미검증만 해제합니다. keyboard 통과로 pointer를 소급 통과시키지 않습니다.

현재 필요한 것은 새로운 거대 하네스가 아니라, 기존 자율 절차 2~3문장과 기존 명세의 구체적인 제품 인수입니다. 위 수정은 제안만 했으며 전역 파일에는 적용하지 않았습니다.
