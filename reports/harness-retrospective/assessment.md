# AI PMS 작업 회고 — 개선 제안

판정: 기존 목적 보존 규칙이 실제 결과물의 제품 인수까지 이어지도록 보강해야 합니다. 부모 분석과 별도 컨텍스트의 Astra 독립 검토는 이 결론에 일치했습니다. 현재 하네스 구성 검사 통과는 UI의 목적 적합성을 증명하지 않습니다.

현재 규칙이 존재한다는 것은 직접 확인했지만, 최초 모든 실패 시점에도 같은 규칙이 있었는지는 이번 조사만으로 확정하지 않았습니다.

범위: 사용자 대화에 나타난 불만과 프로젝트 원문/명세/영수증, 현재 전역 절차와 Kit 정본을 대조했습니다. 전역 설정·훅·메모리·제품 코드는 변경하지 않았습니다. 아래는 반영 후보입니다.

## 확인한 실패와 기존 방어

| 관찰 | 현재 근거 | 판정 |
|---|---|---|
| 중앙 다중 사용자 목적이 개인 Phase 도구 제안으로 축소됨 | PRODUCT-INTENT.md 원래 요청/이전 작업의 처리 | 목적 변경 금지 규칙은 존재. 실행에서 목적을 보존하지 못한 기록 |

후속 사용자 요구가 이전 요구를 구체화하거나 변경한 부분도 있습니다. 모든 재설계를 최초 요구 위반으로 취급하지 않습니다. 최신 '별도 페이지'가 앞선 '하단 상세'를 대체한 것은 정상적인 요구 변경입니다.

## 최소 개선 후보

1. **목적을 행동 가능한 인수 질문으로 고정** — 기존 spec에 '사용자는 무엇을 알아야 하고 어떤 판단/행동을 할 수 있어야 하는가'를 쓰고 원문→관리 질문→필요 데이터→화면/경로→확인 방법을 연결합니다. 데이터가 많다는 이유로 인수를 대체하지 않습니다. UI 외에는 CLI/API/문서 등 실제 결과물에 맞는 인수로 적용합니다.
2. **코드 검사와 제품 인수를 분리** — 테스트/빌드/정합성 통과는 기술 증거입니다. UI 변경은 실제 렌더·상호작용과 설명 없이 목표/현재 단계/다음 행동을 찾을 수 있는지 별도로 확인합니다. 부모/검토자의 평가는 자체 제품 평가이며 실제 사용자 수락을 가장하지 않습니다. 모든 작업에 브라우저/패널을 강제하지 않습니다.
3. **사용자의 목적상 거절도 루프 실패로 처리** — 최초 거절부터 실패한 사용자 경로/판단과 구현 가정을 기록합니다. 명백한 목적 불일치는 즉시 전환합니다. 같은 접근을 두 번 거절받거나 검사에서 두 번 실패하면 동일 접근 세 번째 시도 전에 가정을 바꿉니다. 구현을 포기하거나 매번 승인받으라는 뜻은 아닙니다. 대체 IA/시각화는 대표 화면 하나로 먼저 확인하고 전체 확장을 진행합니다.
4. **실패한 경로와 성공 증거를 같은 단위로 묶기** — 포인터 실패를 keyboard/DOM click으로 대신한 경우 원래 경로는 미검증입니다. 합성 검사, 실제 로컬 전달, 원격 사용자 전달, 배포 파일 대조의 수준을 보존합니다. 영수증은 대상 버전·검사 범위·미검증 경로를 포함하고 영향을 받는 변경 뒤 오래된 성공을 재사용하지 않습니다.
5. **정본 하나와 현재 상태 하나 유지** — 공통 작업 절차는 autonomous_coding.md, 위임 절차는 handoff/SKILL.md, 제품 인수는 기존 spec에 둡니다. AGENTS.md는 포인터를 유지합니다. NEXT_SESSION.md의 여러 '최신' 제목은 현재 하나+과거 이력으로 정리할 후보입니다. 새로운 문서/스키마/훅이 핵심 해법은 아닙니다.

## 반영 위치와 기계화 경계

- ~/.codex/docs/autonomous_coding.md: 완료의 증거 범위, 목적상 거절과 재시도, 동일 경로 검증을 짧게 보강.
- ~/.agents/skills/handoff/SKILL.md: §1/§5에 결과를 써먹는 사람의 인수 질문과 부모 통합 책임을 보강. 기존 schema/intent guard를 다시 만들지 않음.
- ~/.claude/harness/build/current_content.py: Kit ko/en 루프 횟수를 정본과 맞추고 기술 검사/제품 인수 범위를 동일하게 안내. 참고 viewer와 중앙 PMS의 제품 지원 경계도 점검.
- 프로젝트 기존 spec/NEXT_SESSION.md: 제품별 행동 시나리오와 최신 상태. WBS/Gantt나 토스 명칭을 전역 철칙으로 올리지 않음.

자동화 가능: 파일/해시/요구 연결, 실제 viewport와 URL 기록, stale receipt, 잘못된 완료/귀속 반례. 사람/독립 검토가 필요한 것: 목적 누락, 의미/이해 가능성, 관리 행동의 유용성. 의미 판단을 Stop/PreToolUse 훅의 전역 차단으로 만들지 않습니다.

## 적용 효과의 확인

다음 유사 작업에서 기능 테스트가 통과하더라도 요구한 관리 질문에 답하지 못하는 대표 결과물을 제품 인수에서 거절할 수 있어야 합니다. 동일 목적상 거절을 받은 세 번째 작업이 같은 가정의 표현만 바꾸는 재시도가 아니어야 합니다. 이 규칙이 있어도 부모 검토가 다시 형식상 PASS만 주면 개선 효과는 확인되지 않은 것입니다.

## 그대로 반영할 수 있는 문장 후보 — 아직 미적용

공통 자율 절차의 기존 완료 문장 보강:
> 실행한 검사의 통과는 해당 검증 범위의 완료 근거입니다. 결과물의 완료는 원래 목적과 인수 경로도 충족해야 하며, UI는 실제 화면과 상호작용을 확인합니다. 기능 검사·제품 인수·사용자 수락을 서로 대신하지 않습니다.

기존 재시도 문장 보강:
> 사용자의 목적상 거절도 실패 근거입니다. 명백한 목적 불일치는 즉시 수정하고, 같은 접근이 두 번 실패하면 세 번째 시도 전에 거절된 결과·원인가설·바꾸는 가정·인수 조건을 기존 명세에 기록하여 접근을 전환합니다. 다른 진행 가능한 작업까지 중단하지 않습니다.

검증 문장 보강:
> 실패한 경로를 다른 입력 방식이나 모의 검사로 대체해 통과했다면 원래 경로는 미검증으로 남깁니다. 증거의 대상 버전과 범위를 보존하고 영향을 받는 변경만 재검증합니다.

Handoff 부모 수용 절에 추가할 후보:
> 요구 원문이 결과물에서 어떤 질문과 행동으로 확인되는지 기존 spec 인수 절에 연결합니다. 부모는 하위의 검사 PASS를 범위 밖의 제품 인수로 승격하지 않으며, 통합 후 사용자가 실패를 지적한 경로를 직접 확인합니다.

Kit 루프 안내 ko/en 교체 후보:
> 명백한 목적 불일치는 즉시 바로잡고, 같은 접근이 두 번 실패하면 세 번째 반복 전에 가정을 확인하거나 접근을 바꿉니다. 다른 진행 가능한 작업은 계속합니다.
> Correct clear goal mismatches immediately. After two failures with the same approach, check assumptions or change the approach before a third attempt. Continue other work that can still progress.

적용 우선순위는 공통 완료/재시도 절차와 프로젝트 인수(P0) → Handoff 및 미검증 경로 기록(P1) → Kit 설명 동기화(P2)입니다. AGENTS 본문 확장, 새 전역 Stop 훅, 새 리뷰 스키마, 상시 다중 모델 호출은 제안하지 않습니다.
