02 · 지금 Kit가 제공하는 것

환경을 대신 운영하는 서비스보다,
설치하고 검증할 실행 자료에 가깝습니다.

자료·코드 제공

지침과 안전 경계

Codex·Claude의 진입 지침, 필요할 때 읽는 작업 절차, 좁은 위험 패턴을 확인하는 안전 훅을 옮깁니다.

DB·배포·API 계약 등 승인 경계를 보존합니다. 기존 승인을 매번 다시 묻는 절차로 만들지 않습니다.

자료·코드 제공

계획·스킬·검증 루프

Handoff는 작업과 근거를 다른 에이전트에 넘기는 절차입니다. 목표를 Phase(단계)·작업·의존성과 인수(완료를 받아들이는) 기준으로 나눕니다. 검증 결과를 읽고 실패를 수정하며, 부모가 통합 결과를 확인합니다.

기술 검사·제품 인수·사용자 수락을 구분합니다. 같은 접근이 두 번 실패하면 세 번째 반복 전에 가정이나 접근을 바꿉니다.

자료·코드 제공

로컬 기록과 명시적 근거

이벤트 기록기, 작업·검사·판단 기록 명령, JSON 템플릿과 전체 필드 설명을 제공합니다. MCP·데이터 참조도 관측과 선언을 구분해 연결합니다.

MCP는 외부 도구를 호출하는 연결 방식입니다. 연결 설정이 있다는 사실과 실제 사용했다는 기록은 다릅니다.

선택해서 실행

중앙 전달용 Live runtime

로컬 기록을 보내는 sender, 인증된 자체 호스팅 중앙 서비스, 증분 갱신 대시보드 실행 자료가 들어 있습니다.

코드를 제공했다고 모든 PC가 연결되는 것은 아닙니다. 목적지·신원·자격·HTTPS·보관 정책은 운영자가 정하고 연결해야 합니다.

무엇이 포함되고, 무엇을 따로 해야 하나요?

기본 이전·검증 대상Codex·Claude. 안내와 구현 ZIP을 받아 기존 설정을 백업·비교·병합하고, 새 세션에서 로드와 실제 호출을 확인합니다.
별도 준비모델·계정·API 키·MCP 로그인/권한·프로젝트별 허용 범위. 설정 파일이나 키를 다른 사람에게 복제하지 않습니다.
선택 외부 도구Ponytail·Graphify는 별도 설치 안내가 있는 도구입니다. Graphify의 코드 관계 지도는 코드를 실행하지 않고 구문 구조(AST)를 분석하는 선택적 보조이며 프로젝트 완료의 필수 증거가 아닙니다.
현재 지원 경계Cursor·Gemini의 외부 도구 설치 안내와 기본 하네스/PMS 훅 지원을 혼동하지 않습니다. 현재 Live Kit의 native hook 안내는 Codex·Claude 대상이며 Cursor·Gemini hook는 미지원입니다.
설치 자료가 실제 적용으로 이어지는 순서

ZIP 확인 → 기존 설정 백업 → 필요한 지침·스킬·훅 병합 → 로컬 검사 → 새 세션의 로드·trust 확인 → 실제 작업 이벤트 확인입니다.

정적 검사 통과는 파일과 일부 동작의 증거입니다. 앱이 훅을 실제로 호출하는지와 원하는 작업 품질이 나오는지는 대상 환경에서 확인해야 합니다. trust는 해당 훅 실행을 신뢰·허용하는 설정입니다. API 키는 외부 서비스를 호출할 자격이며 Kit에서 복사하지 않습니다.

03 · 원래 목적과 관리 단위

사람을 고르면 목표가 보이고,
계획을 열면 남은 일이 보여야 합니다.

이벤트 개수가 많다는 사실을 진행률이나 성과로 바꾸지 않습니다.

사람 → 프로젝트사람별 여러 목표. 공동 프로젝트는 하나의 project ID와 계획을 공유합니다.
목표 → Phase → 작업Phase는 단계, 원자 작업은 담당자·의존성·완료 조건이 있는 실행 단위입니다.
작업 → 문서·검사·판단계획 이유와 기준 버전, 실패/수정/통과, 현재 산출물과 승인 근거를 연결합니다.
연결한다: 사람이 맡는다 → 목표를 구체화한다 → 작업한다 → 근거로 확인한다

사람이 먼저 볼 네 가지

프로젝트 목표: 무엇을 이루려 하는가?
단계 목표: 중간에 무엇을 달성해야 하는가?
참조: 어떤 API·MCP를 참고했는가?
달성 상태: 어느 단계까지 확인됐는가?

사람 선택→프로젝트→단계 상세로 이동합니다. WBS·검사·세션·조직 지표는 별도 분석 근거에 보존합니다. 단계 달성과 최종 인수는 구분합니다.

세션과 조직 목표도 연결

세션의 시작 목표·담당 작업·종료·인수 기록을 봅니다. 세션이 종료됐다는 사실과 목표가 달성됐다는 판단은 구분합니다.

회사·팀의 북극성은 함께 바라보는 핵심 성과 지표입니다. 정의·기준값·목표값·기간·실측 근거와 기여 연결의 제안/확인을 기록합니다.

테스트 통과는 기술 검증입니다. 고객 문제 해결이나 사업 지표 달성은 별도의 관측이 필요합니다.

가상 예시 · Alice와 Bob의 고객 지식 검색 프로젝트
01 목표·인수 기준단계 완료
02 구현·검증Bob 정책 합의 막힘
03 인수·후속 책임사람 판단 남음

이 도해의 막대는 설명용 상태 표현이며 실제 달력·실측 진행률이 아닙니다. 공개 대시보드의 일정도 명시한 가상 fixture입니다.

완료를 기계적으로 판정하는 조건

필수 작업, 단계별 종료 검사, 프로젝트 전체 인수 검사와 필요한 사람 승인이 현재 계획·산출물에 대해 충족되어야 합니다. 검사 하나의 통과만으로 프로젝트를 완료 처리하지 않습니다.

문서·테스트 기준·산출물 버전이 바뀌면 과거 통과나 승인도 재검토합니다. 근거가 없으면 미관측, 오래됐으면 재검증 필요로 남깁니다.

이 계산은 선언한 계획과 검사 범위 안에서 작동합니다. 계획에서 빠뜨린 요구사항까지 자동 보증하지 않으며, 파일 manifest와 runner 표기도 외부 서명의 신뢰 보증은 아닙니다.

04 · 하나의 가상 사례를 끝까지

기록되는 활동과 확인된 완료는
서로 다른 경로로 들어옵니다.

고객 지식 검색 목표를 Alice와 Bob이 맡았다고 가정합니다. 아래 단계를 누르면 현재 위치와 기록·판단의 책임이 바뀝니다.

01사람이 정한다결과 · 범위 · 완료 기준
02각 PC에 기록한다훅 이벤트 + 명시적 작업 기록
03현재 결과를 검사한다runner · 문서 · 사람 승인
04sender가 전달한다로컬 보관 → ACK → 중앙 반영
05화면에서 판단한다목표 · 막힘 · 후속 개선
사람의 명시적 결정

출처 없는 답변을 차단한다는 완료 기준을 정합니다.

요구사항과 계획 이유, Phase·작업·의존성, 테스트 플랜을 기록합니다. Alice와 Bob의 책임을 같은 프로젝트 ID에 연결합니다.

훅은 “왜 이 목표를 골랐는지”를 스스로 확정할 수 없습니다. 목표와 성공 기준은 사람이 확인한 선언이 필요합니다.

막힘 상세의 실제 관리 행동: Bob이 Alice에게 중복 질문을 기존 요청으로 재사용할지 새 요청으로 처리할지 확인합니다. 합의 내용을 문서에 남기고, Bob이 정책을 반영한 검사를 실행합니다. 화면은 이 예시의 결정을 실행하거나 승인을 대신하지 않습니다.
어떤 데이터를 어디에서 가져오는가?
훅 관측지원 이벤트의 시각·세션/Agent·도구 호출·결과, 식별 가능한 MCP 서버/tool과 허용된 논리 자원 참조. 누락되면 unknown으로 남깁니다.
명시적 기록목표·위임·Phase·작업·계획 변경 이유·테스트 설계 이유·막힘·다음 행동·사람 판단. Handoff 가져오기와 별도 기록 명령을 사용합니다.
검증 실행runner가 검사한 명령·종료코드·시각·기준 버전·산출물 manifest를 연결합니다. 가져온 “통과” 선언과 실제 runner 관측은 구분합니다. runner는 검사를 실행하는 프로그램이며, manifest는 검사에 연결한 파일과 버전·해시의 목록입니다.
중앙 투영원본 기록을 사용자·환경·프로젝트에 귀속시키고, 현재 상태와 관리 항목으로 계산합니다. 실제 데이터 내용이나 키를 무분별하게 수집하지 않습니다.
05 · 어떻게 구현했고 무엇을 확인했는가

세 종류의 증거를 나눠 보면,
현재 위치를 과장 없이 설명할 수 있습니다.

공개 자료·화면

Kit + 합성 대시보드

한영 안내·구현 ZIP·JSON 템플릿/필드 설명, 사람 필터 → 공동 WBS → 별도 작업 상세를 공개했습니다.

실제 한영/모바일 화면·버튼·경로와 공개 파일 일치를 확인했습니다. 공개 Vercel 앱은 private 로그 수신기가 아닙니다.

로컬 합성 실행

중앙 전달 runtime

sender·중앙 service·인증·증분 조회/화면 반영을 구현했습니다. 로컬 HTTP 검사와 합성 7 writer 파일럿을 실행했습니다.

재시작·중복·충돌·기록 실패·잘못된 완료 판정 등의 반례를 검사했습니다. 실제 서로 떨어진 사용자 PC 운영 증거는 아닙니다.

남은 운영 인수

실제 두 사용자 환경

native 앱의 훅 호출부터 원격 sender ACK, 중앙 기록과 브라우저 반영까지 같은 event ID로 대조해야 합니다.

실제 참여자·권한·HTTPS 목적지·보관 범위와 운영 부하/장애 조건을 확인해야 합니다. 전체 제품 완료로 선언하지 않았습니다.

구현 구조를 코드 이름과 연결하기

기록 계층logger.py가 JSONL 이벤트를 남깁니다. connectivity.py가 MCP·자원 메타데이터를 정리하고, 작업/목표 명령이 의미 있는 선언을 별도 기록합니다.
전달 계층live_sender.py가 이벤트와 관리 기록 변경을 전송합니다. 내구성 outbox와 ACK로 재전송을 다룹니다. 중앙 서비스가 보내는 주체(writer)의 자격과 사용자/환경/허용 프로젝트 귀속을 대조합니다.
계산 계층live_service.py와 portfolio/work/management/operations가 원본을 보관·투영하고 현재 기준의 작업·세션·검사·조직 목표 상태를 계산합니다.
표현 계층자체 호스팅 대시보드는 같은 origin의 인증된 API에서 cursor 이후 변경을 polling합니다. 공개 예시는 별도의 합성 정적 snapshot으로 구동합니다. snapshot은 특정 시점에 계산한 현황 파일입니다.
실시간과 신뢰성을 좀 더 정확히 이해하기

현재 sender와 화면 조회는 각각 기본 2초 주기 polling입니다. polling은 바뀐 기록이 있는지 반복 조회하는 방식이며, websocket 스트리밍은 아닙니다. JSON을 한 번 붙여넣는 공개 샘플과, 레코드별 전송·cursor 증분 조회가 있는 자체 호스팅 runtime을 구별해야 합니다.

ACK는 수신 완료 응답, outbox는 전달 전/재시도 기록의 로컬 보관함입니다. 원본 record와 version/hash 기준으로 중복과 충돌을 다루며, 성공 기록만 남겨 실패를 감추지 않습니다.

현재 파일 기반 로컬 파일럿에는 저장·receipt 한도가 있습니다. 이 검사는 조직 규모의 부하·가용성·운영 SLA를 입증하지 않습니다.

runtime은 실행에 필요한 프로그램 묶음입니다. 같은 origin은 화면과 API의 출처가 같다는 뜻이며, API는 시스템이 데이터를 주고받는 창구입니다. cursor는 어디까지 읽었는지 표시하는 위치, receipt는 처리·검증 사실을 남기는 영수증, SLA는 서비스 수준에 대한 약속입니다.

06 · 앞으로의 방향

다음 단계는 기능을 더 나열하기보다,
실제 환경에서 끝까지 연결하는 것입니다.

아래는 다음 인수와 확장 방향입니다. 출시 일정이나 이미 검증한 성능을 뜻하지 않습니다.

1
먼저 확인

실제 두 사용자 연결

각 PC에서 native hook가 정상 기록하는지 확인하고, 동일 event ID로 sender ACK → 중앙 원본 → 세션/작업 → 브라우저 갱신을 대조합니다. 연결 실패와 지연도 화면에 드러나야 합니다.

2
운영 조건

신원·권한·보관·장애 인수

참여자와 조직/프로젝트 조회 범위, HTTPS 운영 목적지, 보관·삭제 정책, 재시작/충돌/부하와 관측 기준을 정합니다. 로컬 자격 구조만으로 기업 운영 보안을 완성했다고 말하지 않습니다.

3
제품 품질

실제 프로젝트에서 관리 질문 검증

개인과 팀이 담당·현재 위치·막힘·다음 행동을 설명 없이 찾는지 확인합니다. 규칙 문서나 테스트 수가 늘었다는 사실 대신, 빠뜨린 인수·반복된 재작업이 줄었는지 근거를 봅니다.

4
확장 제안

개발 이후 운영 문제까지 연결

배포 후 지표·성능 저하·장애를 다시 목표와 작업·검증으로 연결하는 개선 루프를 지향합니다. 해당 운영 자동화와 타 도구 hook 확대는 현재 검증 완료 범위가 아닙니다.

중앙 관리가 하는 일: 사람을 활동량으로 자동 평가하는 대신, 목표·완료 조건·실패 근거·판단할 일을 연결합니다. 철칙·하네스·루프·스킬·MCP 개선 제안도 어느 시도와 검증에서 나왔는지 남기고 효과는 따로 확인합니다.
