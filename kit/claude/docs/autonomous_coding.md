# 자율 작업 절차

큰 변경이나 반복 실패가 있을 때만 읽습니다. 승인 경계는 `~/.claude/CLAUDE.md`를 따릅니다.

- 작업의 위험·의존성에 맞는 계획을 세웁니다. 파일 수만으로 Plan 모드나 추가 승인을 강제하지 않습니다.
- 버그 수정은 재현을 확인하고, 기존 기준선과 구현 뒤 합격 기준을 구분합니다. 재현 테스트의 기대 실패는 정상일 수 있습니다.
- 마지막 수정 이후 관련 검증 결과를 확인합니다. Stop 훅은 보조 검사이며 충분한 검증 범위를 대신 판단하지 않습니다.
- 실행한 검사의 통과는 해당 검증 범위의 완료 근거입니다. 결과물의 완료는 원래 목적과 인수 경로도 충족해야 하며, UI는 실제 화면과 상호작용을 확인합니다. 기능 검사·제품 인수·사용자 수락을 서로 대신하지 않습니다. 실행하지 못한 범위는 이유와 함께 표시합니다.
- 사용자의 목적상 거절도 실패 근거입니다. 명백한 목적 불일치는 즉시 수정하고, 같은 접근이 두 번 실패하면 세 번째 시도 전에 거절된 결과·원인가설·바꾸는 가정·인수 조건을 기존 명세에 기록하여 접근을 전환합니다. 다른 진행 가능한 작업까지 중단하지 않습니다.
- 큰 작업은 독립적으로 검증 가능한 단위로 나누고 결과를 통합합니다. 기존 테스트 삭제·skip은 현재 요청의 승인 범위를 확인합니다.
- 실패한 경로를 다른 입력 방식이나 모의 검사로 대체해 통과했다면 원래 경로는 미검증으로 남깁니다. 증거의 대상 버전과 범위를 보존하고 영향을 받는 변경만 재검증합니다.
