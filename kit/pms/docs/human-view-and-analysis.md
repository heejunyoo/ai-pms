# 사람이 보는 현황과 AI가 사용하는 근거

2026-10-03 사용자 요구를 반영한 화면·분석 준비 기준입니다. 중앙 PMS의 목적은 여러 사용자가 여러 환경에서 진행하는 목표를 관리하는 것입니다. 로그를 많이 보여주는 것이 목적이 아닙니다.

## 기본 화면

사람 선택 → 참여 프로젝트 → 한 프로젝트의 단계 → 한 단계 상세로 이동합니다. 기본 화면에는 프로젝트 목표, 각 Phase의 목표, 참고한 API·MCP, 달성 상태만 둡니다. 공동 프로젝트의 참여자는 같은 프로젝트 카드에 표시합니다. 단계 달성과 프로젝트 최종 인수는 별도로 표시합니다.

작업 WBS, 검사 명령, 시도 이력, 문서 버전, 세션과 조직 지표는 별도 분석 근거 화면에 보존합니다. 기본 화면을 줄여도 원본 수집·중앙 전달·검증 조건은 줄이지 않습니다. 회사·팀 목표 연결은 기존 명시적 기여 기록을 사용하며 모델이 추정한 연결을 확정된 기여로 바꾸지 않습니다.

참조는 설정·선언·호출 관측·데이터 획득을 구분합니다. 프로젝트 연결을 특정 Phase의 참조로 추정하지 않습니다. 단계 연결이 없으면 없다고 표시합니다. 실제 프로젝트 로컬 화면의 상태와 참조는 기존 문서에서 가져온 이력이며 현재 훅 호출·runner 통과 증거가 아닙니다. 목표 설명을 관리용으로 재구성한 항목도 원래 계획으로 위장하지 않습니다.

## 로그에 부여할 의미

| 입력 근거 | 분석할 질문 | 관리자에게 보여줄 결과와 행동 |
|---|---|---|
| 사람·프로젝트 목표, 대상, 성공 기준, 범위, 조직 기여 | 서로 다른 사람이 같은 결과를 중복 구현하고 있는가? | 모델이 제안한 후보 쌍, 유사한 이유, 다른 범위, 확인할 목표 링크. 사람이 협업·독립 유지·기각을 판단 |
| 검사 실패→수정→재검사, 작업·계획·산출물 버전 | 같은 원인에서 반복해서 막히는가? | 반복 원인과 연결된 시도, 도움 요청 또는 검증 절차 변경 제안 |
| 현재 요구사항·작업·테스트 계획·승인 | 완료 선언에 필요한 증거가 빠졌는가? | 결정적인 검증 누락은 기존 판정기로 찾고 AI는 의미와 후속 행동을 설명. AI가 완료 상태를 올리지 않음 |
| API·MCP 설정/요청/결과와 명시적 자원 참조 | 접근 실패·맥락 부족·공통 의존성이 있는가? | 필요한 권한·참고 자료·재사용 가능한 맥락 제안. 호출 성공을 내부 데이터 획득으로 해석하지 않음 |
| 스킬·철칙·하네스 변경과 전후 실패 기록 | 어떤 작업 규칙을 개선할 수 있는가? | 적용 범위와 근거가 있는 개선 후보. 후속 관측으로 효과 확인; 로그 수를 효과나 생산성으로 환산하지 않음 |
| Handoff·결정·문서 버전·범위 변경 | 맥락이 유실되거나 서로 모순되는가? | 충돌한 결정과 담당자의 확인 요청 |

## 목표 중복 경고의 기준

같은 기술, 키워드 또는 주제만으로 중복이라고 판정하지 않습니다. 원하는 결과·대상 사용자·성공 기준·범위가 실질적으로 겹치는지 비교합니다. 같은 공동 프로젝트에 배정된 작업은 정상 협업일 수 있습니다. 기존 프로젝트/기여 연결을 먼저 읽고 중복 후보 제안과 확정 판단을 구분합니다. 회사 목표가 같아도 구현 범위가 다르면 독립 유지가 가능합니다.

분석 결과에는 근거 ID/링크, 분석 대상 범위와 버전, 모델 식별자와 분석 시각, 이유, 권장 행동, 최신성, 사람의 수락·기각을 남겨야 합니다. 근거 없는 점수나 경고를 만들어 넣지 않습니다. 계획이나 목표가 변경되면 이전 제안을 다시 확인합니다. 모델 결과로 프로젝트를 자동 합치거나 목표 귀속·완료·권한을 변경하지 않습니다.

## 이번 구현과 다음 연결

구현: 기본 화면의 최소 정보 투영, 별도 근거 경로, 기존 완료 판정 보존. 준비: `scripts/prepare_goal_analysis.py`가 정규화 스냅샷에서 목표 비교용 입력을 생성합니다. 원본 이벤트·명령·개인 경로를 입력에 넣지 않으며 외부 모델을 호출하지 않습니다. 입력 패킷 자체는 분석 결과가 아닙니다.

아직 미구현: 모델 실행·비용/접근 정책, 근거를 대조하는 결과 검증기, 경고 승인·기각 저장과 알림. 공개 샘플에 가짜 AI 경고를 넣지 않았습니다. 실제 분석 연결 시에는 권한 범위 안의 목표만 비교하고 근거 없는 결과를 폐기해야 합니다. 실제 프로젝트 패킷은 비공개 로컬에 유지합니다.

## 운영과 공개의 경계

기존 Kit logger는 지원 이벤트별 JSONL, health, 명시적 작업·검사 기록을 제공합니다. opt-in sender와 자체 호스팅 중앙 서비스는 개별 변경·durable ACK·cursor 증분 조회를 제공합니다. 훅만으로 목표·Phase의 의미를 확정할 수 없으므로 선언한 계획을 함께 전달해야 합니다. 공개 Vercel은 합성 정적 샘플이며 private 중앙 수신기가 아닙니다. 실제 앱 훅 trust와 원격 두 사용자 전달은 별도 운영 인수 대상입니다.
