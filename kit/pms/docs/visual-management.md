# 프로젝트 계획을 읽는 화면

이번 재구성의 목적은 전체 계획, 현재 작업, 남은 완료 조건을 같은 WBS에서 읽는 것입니다. 사람이 선택되더라도 공동 프로젝트의 다른 담당자와 전체 단계는 유지합니다. 목표와 상태를 가리는 화살표 카드·이름 없는 색 막대와 중복 세션 목록이 전문가 소스 검토에서 확인된 문제였습니다.

## 기본 정보와 시각화

목록은 프로젝트 목표·참여자·진척·판단 필요를 비교합니다. 프로젝트 하나를 열면 Phase와 원자 작업을 계층형 행으로 정렬하고 담당·상태·종료 검사·최종 인수를 연결합니다. Phase의 작업을 펼치고 하나의 작업 상세에서 원인·다음 행동·완료 조건으로 내려갑니다. 상태는 색뿐 아니라 텍스트와 기호로 읽으며, 선택한 사람의 책임은 전체 계획 안에서 강조합니다.

날짜를 선언하고 검증된 일정만 날짜축으로 사용합니다. 일정 없는 계획은 단계축이며 기간·납기·의존성을 추측하지 않습니다. 작업 완료 수를 노력이나 생산성의 비율로 바꾸지 않습니다. 문서상 완료와 현재 검사 통과, 로컬 검증과 최종 인수는 별개입니다.

## 세션 수가 뜻하는 것

세션은 수집된 실행 이력입니다. 같은 목표에 구현·검사·재시도 실행이 이어질 수 있고, 한 세션이 여러 작업에 연결될 수 있습니다. 사용자·환경·출처·원본 프로젝트를 보존하며 비슷한 제목이나 같은 원시 ID만으로 합치지 않습니다.

실행 이력은 목표·사람·시각·실행 상태·목표 확인을 한 번 표시하고 ID·원문은 필요할 때 엽니다. 종료된 실행도 목표 검사에 실패하거나 근거가 없을 수 있습니다. 목표 없는 이전 기록과 수집 기록 없음은 구분합니다. 문서만 가져온 실제 프로젝트 미리보기에 성공 세션이나 현재 runner 결과를 만들지 않습니다.

## 근거를 여는 목적

일반 진입은 작업 결과, 실행 이력, 참고 자료처럼 사용자가 확인할 질문을 중심으로 합니다. 검사·문서·MCP·계획·인계·판단 원문은 해당 질문의 상세로 연결합니다. 기존 기술 기록 기능과 이전 주소는 보존하지만 9개 스키마 분류를 기본 탐색으로 강요하지 않습니다. 회사·팀 목표의 연결과 측정은 선언·확인·실측을 구분하고 개인 목표에 조직 계층을 강제하지 않습니다.

## 검토와 실제 인수

Astra는 WBS 숨김·Phase 작업 통로 삭제·이름 없는 막대 문제를 소스로 확인했습니다. [설계 제안](../reports/visual-redesign/astra-meeting.md)을 작성했지만 사용량 한도로 구현 후 최종 검토를 마치지 못했으며 [중간 의견](../reports/visual-redesign/astra-input.md)에 그 범위를 남겼습니다. [제품·정보 디자인 검토](../reports/visual-redesign/ux-meeting.md)는 별도 모델 관점이며 실제 고객 인터뷰가 아닙니다.

명세·계획은 specs/ai-pms-visual-management/에 있습니다. 명령 회귀 검사는 원본 모델 불변, 공유 계획·담당·세션 귀속과 잘못된 완료 반례를 확인합니다. 실제 데스크톱의 가독성·정렬·줄바꿈·선택·상세 이동·뒤로·새로고침은 별도 실제 브라우저 인수입니다. 모바일은 사용자 지시로 제외합니다. 브라우저가 연결되지 않으면 UX 완성으로 보고하지 않습니다.

최종 구현·검사·공개 반영과 실제 화면 인수 여부는 같은 폴더의 integration-proof.json과 release-proof.json에서 확인합니다. 정적 합성 공개 샘플과 비공개 실제 프로젝트 미리보기의 자료는 분리합니다. 원격 실제 두 사용자 전달·앱 훅 trust·실제 모델 분석은 이번 화면 변경으로 인증되지 않습니다.
